Predictive AI on LinuxONE: current runtime
=========================================

The assembled application was tested in Docker on LinuxONE s390x.
See docs/DEPLOYMENT.md for build prerequisites and docs/TECH_STACK.md for
observed versions. Older host-apt instructions are superseded by this setup.

Model: backend/model/recommender.joblib
Training estimator version: scikit-learn 1.4.1.post1
Pinned application versions: scikit-learn 1.4.1.post1, NumPy 1.26.4
Application container: Python 3.11, not the host development Python 3.12.

Do not install the newest scikit-learn over these pins for this artifact.
An earlier Docker test caught a 1.9.1/1.4.1.post1 mismatch before deployment.

Read-only runtime test, from the repository root on LinuxONE:

    docker compose run --rm --no-deps -T app python - <<'PYTEST'
    import warnings
    import numpy as np
    from sklearn.exceptions import InconsistentVersionWarning
    warnings.simplefilter("error", InconsistentVersionWarning)
    from backend.predictive import load_model
    bundle = load_model()
    model = bundle["model"]
    scores = model.predict_proba(np.zeros((1, len(bundle["item_ids"])), dtype=int))
    assert np.isfinite(scores).all()
    assert scores.shape == (1, len(model.classes_))
    assert np.allclose(scores.sum(axis=1), 1)
    print("Predictive runtime: PASS")
    PYTEST

This verifies compatibility and inference only, not predictive accuracy.

Synthetic training/evaluation
-----------------------------
The generator uses its own SQLite database and CSVs, not Supabase.
backend/schema.sql is retained for this purpose; it is not the live schema.
In a separate training environment with the matching scikit-learn/NumPy and
Faker/Matplotlib/Pillow dependencies installed, the scripts are:

    python evaluation/seed_synthetic.py --reset
    python evaluation/train_recommender.py

--reset replaces local synthetic data. Training overwrites the local model
artifact and metrics; do not run casually in the deployment checkout.
Review and commit any intentionally retrained artifact/evaluation together.
Do not assume training packages are installed in the minimal app image.

Feature mapping
---------------
Supabase menu UUIDs use explicit nullable menu_items.model_item_id values.
Migration 003 maps six matching Store 1 foods to training IDs 1 through 6.
Never derive model identity from sorting names, row order, or UUID suffixes.
Store 2 and other unmapped foods must not inherit unrelated trained IDs.

Customer histories are personal completed orders for one business. Owner
histories are completed orders for the session owner business. Model-ranked
pairings require measured co-occurrence evidence; sparse history can produce
popularity fallback or explicitly labeled random exploration. The live
examples verified during integration were popularity fallbacks.

Committed evaluation/results/metrics.json uses synthetic order-grouped folds.
Report it as synthetic evaluation; it is not proof of real-world sales lift.
